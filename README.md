# crossfirelegion

Crossfire Legion Windows 런처. 한국어 UI, GitHub Releases 업데이트, 백업과 원본 복원이 가능한 모든 유닛 생산 패치를 제공합니다.

## 실행

1. [최신 릴리스](https://github.com/japanoxx-afk/crossfirelegion/releases/latest)의 `CrossfireLegion-Launcher-버전.zip`을 다운로드하고 쓰기 가능한 폴더에 압축을 풉니다.
2. `Launcher.exe`를 실행합니다. 게임 경로를 지정하고 게임을 종료한 상태에서 **모든 유닛 패치 적용**을 누릅니다.
3. Steam에 로그인한 뒤 **Steam으로 게임 실행**을 눌러 사용자 지정/오프라인 경기에서 생산 메뉴를 확인합니다. 설치 폴더 쓰기 권한이 없을 때만 런처를 관리자 권한으로 실행하세요.
4. **원본 복원**으로 적용 전 DLL을 되돌릴 수 있습니다.

기본 게임 경로: `C:\Program Files (x86)\Steam\steamapps\common\Crossfire Legion (Demo)`

Windows 10/11의 .NET Framework 4.8을 사용합니다. 게임 파일은 배포물에 포함하지 않습니다.

## 긴 GC 정지 완화를 위한 시작 설정 (v0.2.18)

2026-10-19 00:09 이후 게임 창 활성 상태의 100ms 초과 지연 39회가 기록됐으며, 모두 같은 구간에 GC가 발생했습니다. 지연은 599.8~846.6ms, 관리 메모리는 1490→1619MB였고 엔진은 incrementalGC=False로 실행됐습니다. 지연 전체 시간을 GC 단독 비용으로 측정한 것은 아니지만 반복 정지의 강한 연관성을 확인했습니다.

Unity 2020.3의 [공식 빌드 후처리 코드](https://github.com/Unity-Technologies/UnityCsReference/blob/2020.3/Editor/Mono/Modules/DefaultBuildPostprocessor.cs)가 증분 GC에 사용하는 `gc-max-time-slice=3`을 boot.config에 설정합니다. 한 번에 긴 정리를 하는 대신 여러 프레임에 작업을 나누는 것을 목표로 합니다. 지원 여부와 실제 활성화는 다음 실행의 `Diagnostics v0.2.18: incrementalGC=True` 로그로 확인해야 합니다. 실제 경기 지연 개선은 아직 확인하지 않았습니다.

기존 시작 설정은 유지하며 동일 키의 중복만 제거합니다. boot.config도 원본 해시 검증·백업·일괄 복원 대상에 포함합니다. 게임 DLL 복사본과 시작 설정의 적용·중복 방지·바이트 단위 원본 복원을 검증했습니다. 원본 복원을 누르면 GC 설정도 원래대로 돌아갑니다. 게임 실행 중에는 파일을 수정하지 않습니다.

## 마우스오버 설명창 및 진단 로그 (v0.2.17)

설명창 위치 계산 중에만 대상 패널을 대입하고, 모든 정상 반환 경로에서 원래 마우스오버 버튼을 복원합니다. HideTooltip이 원래 버튼과 대상을 비교하는 조건을 보존하여 마우스를 벗어나면 설명창이 닫히도록 수정했습니다. 런처에 **진단 로그 폴더 열기** 버튼을 추가했습니다.

기존 60초 집계에 더해 100ms 초과 프레임의 지연 시간, 같은 구간의 GC 횟수 변화, 관리 메모리 MB, 창 활성 여부를 기록합니다. 개별 지연 기록은 최대 초당 1개로 제한하며 강제 GC를 하지 않습니다. 초기 로그에는 엔진의 incrementalGC 지원/활성 상태가 기록됩니다. 메뉴/로딩/백그라운드도 포함되며 네트워크 RTT 측정값은 아닙니다.

2026-10-17 02:22~02:34 구간에서 약 493~561ms의 긴 지연이 GC 발생과 겹쳤습니다. 네트워크 원인 여부는 기존 로그로 확정할 수 없습니다. 모드의 반복 속성 읽기를 캐시된 호출로 바꾸어 리플렉션 호출 비용을 줄였습니다. 실제 경기에서 끊김 감소 여부는 아직 확인하지 않았습니다.

## GC 관련 반복 메모리 할당 감소 (v0.2.16)

2026-10-16 00:14~00:17 성능 기록에서 100ms 초과 지연 4회 모두 같은 렌더 간격에 GC가 발생했습니다. 최대 지연은 590.6ms였습니다. GC와 지연의 동시 발생을 확인했지만 전체 지연 시간을 GC 단독 비용으로 측정한 것은 아닙니다.

생산창 재구성의 중복 검사 집합과 임시 목록을 선택 데이터별로 재사용하고 finally에서 참조를 비웁니다. 약한 참조 테이블을 사용해 선택 데이터 수명을 늘리지 않습니다. 유닛 참조 변환은 캐시된 델리게이트로 호출해 매번 리플렉션 인자 배열을 생성하지 않습니다. 동적 컴파일이 불가능한 환경에서는 원래 호출로 돌아갑니다.

동일한 46버튼 모의 UI를 20,000회 갱신한 .NET 비교에서 Gen0 수집 28→13회, 처리 시간 250.7→173.7ms였습니다. 실제 Unity 경기의 FPS/끊김 개선율은 아니며 추가 플레이 확인이 필요합니다. GC를 비활성화하거나 강제 수집을 반복하지 않습니다. Unity의 [메모리 관리 설명](https://docs.unity3d.com/jp/2020.3/Manual/performance-incremental-garbage-collection.html)도 참고했습니다.

## 누락된 한국어 유닛·능력 번역 (v0.2.15)

영어에는 있지만 한국어 언어 파일에 빠진 유닛·지휘관·능력 관련 항목 82개를 보완했습니다. 스크린샷의 LocID:23707/23708은 범블비 이름/설명입니다. 코브라, 히드라, 정예 유닛, 관련 기술과 업그레이드 설명도 포함합니다. 영어 원문을 바탕으로 작성한 비공식 한국어 번역이며 기존의 정상 번역은 유지합니다.

한국어 사전을 불러올 때 메모리에서 누락 항목만 채웁니다. 언어 파일 자체는 수정하지 않고 영어 및 다른 언어도 변경하지 않습니다. 자리표시자 {0}를 보존합니다. Carbon.Localization.Core.dll을 백업·복원 대상에 추가했습니다. 실제 경기의 텍스트 표시와 줄바꿈은 추가 확인이 필요합니다.

v0.2.11 실제 플레이의 23:49~23:53 기록에서 p95는 19ms, 분당 100ms 초과 지연은 2~5회, 최대 지연은 579~630ms였습니다. 같은 구간의 GC 횟수도 각각 2~5회로 일치하지만 이것만으로 인과관계를 확정하지 않습니다. 새 로그의 `over100_with_gc`는 100ms 초과 렌더 간격 중 GC 횟수가 증가한 구간 수를 기록합니다. 실제 경기 화면 배치 및 끊김 해결은 아직 검증하지 않았습니다.

## 반복 UI 비용 감소 및 끊김 진단 (v0.2.11)

생산창으로 등록되지 않은 UIList의 갱신은 즉시 반환해 UI 계층 탐색과 리플렉션 호출을 생략합니다. 실명·치명타 판별은 속성 객체별 약한 참조 캐시에 보관해 동일한 효과를 읽을 때 반복 조회하지 않습니다. UIList 해제 시 등록 정보를 제거해 이전 화면의 UI를 계속 참조하거나 갱신하지 않습니다.

60초마다 `[CFL All Units] Render intervals` 진단 한 줄을 게임 로그에 남깁니다. Unity 프레임 번호로 중복 Canvas 호출을 제외하고, 렌더 콜백 간격의 p95(1ms 구간, 500은 499ms 초과), 최대값, 50/100ms 초과 횟수, GC 0세대 수집 횟수를 집계합니다. 프레임마다 파일을 쓰거나 컬렉션을 만들지 않습니다. 메뉴·로딩·백그라운드 시간도 포함되므로 이 숫자만으로 CPU/GPU 병목이나 GC 원인을 확정할 수 없습니다.

확인한 기존 로그는 Unity 2020.3.7f1 / RTX 4080이며, 최근 경기 중 지속적인 예외 폭주는 발견되지 않았습니다. 직접 GC 호출은 조사한 게임/Carbon 최상위 메서드에서 경기 시작 시점에 발견됐습니다. 런타임의 자동 GC나 다른 병목까지 배제한 결과는 아닙니다. 이번 변경은 확인된 모드의 불필요한 작업을 줄이며, 실제 경기의 끊김 해소 여부는 다음 플레이 기록으로 확인해야 합니다.

## 실명·치명타 전투 텍스트 축소 (v0.2.10)

`fx_prfb_status_blind`와 `fx_prfb_status_critical` 상태 표시의 크기를 원본의 50%로 줄입니다. 이 두 효과는 유닛 크기에 따른 자동 확대도 하지 않도록 합니다. 대상은 FX 프리팹 경로로 확인하며, 치명적 체력 상태의 방어막 효과 등 이름이 비슷한 다른 효과는 변경하지 않습니다.

원본 크기를 읽을 때 배율을 적용하므로 반복 표시해도 계속 작아지지 않습니다. 효과 생성 경로에만 적용하며 화면 전체 텍스트 검색이나 프레임별 처리는 추가하지 않습니다. 대상 구분·50% 배율·반복 호출·유닛 크기 확대 제한 및 실제 DLL 복사본의 적용·원본 복원을 검증했습니다. 실제 경기 화면의 가독성은 아직 직접 확인하지 않았습니다.

## 생산창 4행 간격 및 UI 반복 부하 개선 (v0.2.9)

아래 3행의 위치는 유지하고, 그 위로 늘어나는 4행째부터 36 UI 단위의 추가 간격을 확보합니다. 녹색 테두리를 강제로 지우는 방식 대신 테두리 높이를 건너뛰도록 배치합니다. Unity의 기본 그리드 배치가 끝난 뒤 필요한 버튼 위치만 보정하고, 화면 높이 계산에도 이 간격을 포함합니다. 일꾼처럼 3행 이하는 원래 위치로 복구합니다.

매 프레임 테두리 오브젝트를 비활성화하던 LateUpdate 및 주기적인 전체 이미지 검색을 제거했습니다. 크기·선택이 같으면 그리드를 다시 설정하지 않고, 변경이 없는 UIList 갱신에서는 후처리를 생략합니다. 리플렉션 메타데이터와 타입 조회는 캐시하고 빈 단축키 슬롯 검사는 첫 12개만 처리합니다. 렌더 시에는 기준 버튼 한 개로 네이티브 레이아웃 재계산 여부를 확인하고, 간격이 초기화됐을 때만 다시 배치합니다.

기존 v0.2.8과 새 런타임의 동일한 모의 UI/46개 버튼/1000회 갱신 비교에서 31.2ms → 15.6ms가 측정됐습니다. 이는 패치 UI 코드의 .NET 테스트 수치이며 실제 게임 FPS나 끊김 해소율을 의미하지 않습니다. 실제 프레임 시간은 아직 측정하지 않았습니다.

게임 로그의 `Set Method not found for 'ID'` 오류도 수정했습니다. 상속된 비공개 속성 설정자를 원래 선언 타입에서 찾아 호출해 speed/pop 효과 생성 시 예외가 나지 않도록 했습니다. 비공개 ID 설정자를 가진 모의 효과로 회귀 검증했습니다.

실행 중인 게임 설치 폴더는 변경하지 않았습니다. 실제 DLL 복사본으로 후크·구버전 갱신·4개 DLL 원본 복원을 검증했습니다.

수정 파일은 `Carbon.Simulation.dll`, `Game.UI.dll`, `Carbon.UI.Unity.dll`이며 원본은 각각 `.cfl-original`로 백업합니다. 전체 상태/복구 기록은 Managed 폴더의 `CflMod.state.json`에 저장합니다. 적용 도중 문제가 생기면 복원하고, 변경된 게임 파일을 발견하면 덮어쓰지 않고 중단합니다. 원본 복원 시 자체 런타임도 제거합니다.

## 런처 업데이트

**런처 업데이트** 버튼은 이 저장소의 최신 정식 GitHub Release를 확인합니다. 새 버전의 `update.zip`과 `update.sha256`을 내려받고 SHA-256, ZIP 구성, 실행 파일 버전을 확인한 뒤 별도 버전 폴더에 설치합니다. 성공하면 `current.txt`를 교체하고 새 런처를 실행합니다. 이전 버전은 남아 있으며 `previous.txt`에 직전 버전이 기록됩니다. 업데이트 실패 시 기존 실행 파일은 유지됩니다. 이 기능은 런처/패처를 업데이트하며, 게임에 패치를 다시 적용해야 할 때는 원본 복원 후 재적용하세요.

## 개발 및 배포

```powershell
./scripts/build.ps1
# 출력: dist/Launcher.exe, build/*.zip

# 원본 게임 DLL을 대상으로 복사본 테스트 (게임을 종료한 상태)
./scripts/test-runtime.ps1 -Version 0.2.3 -GamePath 'C:\Program Files (x86)\Steam\steamapps\common\Crossfire Legion (Demo)'
# 결과: dist/versions/0.2.3/test-result.txt
```

코드 변경을 커밋한 뒤 다음 명령으로 새 버전을 배포합니다.

```powershell
./scripts/release.ps1 -Version 0.2.4
```

이 명령은 `version.txt`를 올리고 커밋·태그·푸시합니다. GitHub Actions가 Windows에서 빌드하고 Release에 런처 ZIP과 업데이트 파일을 게시합니다. 매 변경 배포 시 버전을 증가시켜야 하며, Actions 성공 이후 사용자의 업데이트 버튼에 반영됩니다. GitHub 인증/저장소 쓰기 권한과 Actions 사용 가능 상태가 필요합니다.

빌드 의존성: Mono.Cecil 0.11.6 (MIT). NuGet 패키지의 고정 SHA-256을 검증합니다. 런처 소스와 배포 설정만 Git에 포함하며 게임 DLL, 세이브 및 개인 설정은 포함하지 않습니다.
