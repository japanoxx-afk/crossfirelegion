# crossfirelegion

Crossfire Legion Windows 런처. 한국어 UI, GitHub Releases 업데이트, 백업과 원본 복원이 가능한 모든 유닛 생산 패치를 제공합니다.

## 실행

1. [최신 릴리스](https://github.com/japanoxx-afk/crossfirelegion/releases/latest)의 `CrossfireLegion-Launcher-버전.zip`을 다운로드하고 쓰기 가능한 폴더에 압축을 풉니다.
2. `Launcher.exe`를 실행합니다. 게임 경로를 지정하고 게임을 종료한 상태에서 **모든 유닛 패치 적용**을 누릅니다.
3. Steam에 로그인한 뒤 **Steam으로 게임 실행**을 눌러 사용자 지정/오프라인 경기에서 생산 메뉴를 확인합니다. 설치 폴더 쓰기 권한이 없을 때만 런처를 관리자 권한으로 실행하세요.
4. **원본 복원**으로 적용 전 DLL을 되돌릴 수 있습니다.

기본 게임 경로: `C:\Program Files (x86)\Steam\steamapps\common\Crossfire Legion (Demo)`

Windows 10/11의 .NET Framework 4.8을 사용합니다. 게임 파일은 배포물에 포함하지 않습니다.

## 싱글플레이 치트 (v0.2.5)

런처 업데이트 후 게임을 종료하고 **모든 유닛 패치 적용**으로 패치를 갱신하세요. 경기 중 **Enter → 치트 입력 → Enter**로 사용합니다. 대소문자를 구분하지 않습니다.

| 치트 | 효과 |
| --- | --- |
| `money` | 내 재료와 연료를 각각 9999로 설정. 필요하면 해당 자원의 현재 보유 한도를 9999까지 올립니다. 인구수는 변경하지 않습니다. |
| `speed` | 내 유닛 생산·업그레이드 및 일꾼의 건물 건설 속도에 100배 배율 적용. 반복 입력해도 중첩하지 않으며 경기마다 다시 입력합니다. |
| `pop` | 생산 인구 한도를 해당 경기의 최대 허용치(HardCap, 기본 데이터는 200)로 설정. 현재 사용 인구는 그대로 유지합니다. |

다른 사람과의 경기, 자동 매칭, 관전, 리플레이에서는 실행하지 않습니다. AI 상대는 허용하며 내 슬롯의 지휘관에게만 적용합니다. 경기 정보를 확인할 수 없으면 실행을 차단합니다. 일반 채팅 문구는 원래 경로를 사용하고, 치트 안내는 로컬 채팅에 표시합니다. 캠페인의 채팅 입력 제한도 해제합니다.

입력/경기 제한/자원 설정은 모의 객체 테스트로 검증했고 실제 설치 DLL의 복사본으로 치트 후크와 적용·복원을 검증했습니다. 실제 경기에서 Enter 입력, 자원 표시 및 생산 완료 시간은 아직 직접 확인하지 않았습니다.

## Steam 연결 오류 수정 (v0.1.2)

기존 런처의 게임 EXE 직접 실행을 Steam 실행 요청으로 변경했습니다. 선택한 폴더가 Steam 설치 매니페스트(`appmanifest_1072190.acf`)와 일치하는지 확인한 뒤 `steam://run/1072190`을 Windows의 Steam 프로토콜 처리기로 전달합니다. 폴더 이름에 Demo가 있어도 실제 설치 매니페스트의 AppID 1072190을 사용합니다. 이미 실행 중인 게임에 중복 실행을 요청하지 않습니다.

오류 화면이 열린 게임을 완전히 종료하고 런처를 업데이트한 뒤 Steam에 로그인한 상태에서 다시 실행하세요. 이 변경은 실행 경로를 수정하며, Steam 계정 인증이나 서버 연결 성공을 보장하지는 않습니다. 동일한 오류가 Steam 라이브러리에서 직접 실행할 때도 발생하면 Steam 온라인 상태와 계정의 게임 이용 권한을 확인하세요.

실행 경로 회귀 검증(실제 게임을 실행하지 않음):

```powershell
./scripts/test-steam.ps1 -GamePath 'C:\Program Files (x86)\Steam\steamapps\common\Crossfire Legion (Demo)'
```

## 패치 범위와 검증 상태

v0.2.0에서는 `RosterHelper.FillRosterScratchpadForCategory`가 진영의 각 슬롯에 속한 모든 대체 유닛을 등록하도록 변경합니다. 기존 v0.1.x의 표시 필터 우회는 제거합니다. 실제 로스터 등록을 통해 생산 능력·업그레이드·기술 초기화에 전체 유닛 목록이 전달됩니다. `SatisfiesRosterRequirement`의 덱 슬롯 번호 비교를 제거하며 로스터 소속 검사와 자원·테크·인구 요구 조건은 유지합니다.

편성 화면의 9개 슬롯과 저장된 덱 형식은 유지합니다. HUD 명령/생산 데이터는 최대 64개를 지원합니다. v0.2.5는 생산창을 원래 하단 위치에 고정하고 4열로 위쪽으로 확장합니다. 이전 버전의 336 UI 단위 위쪽 여백은 제거했습니다. 화면 높이를 넘을 때만 생산창 전체를 같은 비율로 축소하며, 버튼이 적은 선택으로 돌아가면 기본 크기로 복구합니다. 일꾼의 건설 C/뒤로 Z 슬롯과 빈칸은 유지합니다.

표시된 녹색 장식 테두리는 `ui_hud_command_ability_BG` 이미지만 숨겨 제거합니다. 왼쪽 유닛 정보창 이미지와 부대 지정 숫자키는 유지합니다. 생산창의 얇은 테두리와 배경은 확장된 창의 크기를 따릅니다.

명령 패널이 직접 소유한 주 버튼 목록만 확장하며, 내부 툴팁·장식·보조 목록은 제외합니다. **v0.2.2는 일반 명령과 건설/복귀 메뉴의 원래 슬롯을 보존합니다.** 일꾼 건설 C는 인덱스 10, 건설 메뉴 복귀 Z는 인덱스 8에 유지됩니다. 기본 12칸 안의 빈 슬롯은 보이지 않는 자리로 유지하여 버튼이 앞쪽으로 압축되지 않게 하고, 확장 영역의 빈 슬롯은 숨깁니다. 추가 생산·업그레이드 버튼은 기존 명령을 덮어쓰지 않는 빈칸에 배치합니다. 기존 단축키 범위 밖의 버튼은 마우스로 누릅니다. `CflRuntime.dll`은 자체 작성한 코드만 포함하며 런처 리소스에서 설치됩니다.

게임을 종료한 상태에서 **모든 유닛 패치 적용**을 누르면 v0.1.x에서 바로 전환됩니다. 적용 후 반드시 **새 경기**를 시작하세요. 이미 생성된 경기/저장 파일의 로스터에는 소급 적용되지 않습니다. AI에도 영향을 줄 수 있고 캠페인 스크립트·온라인 호환성은 검증되지 않았습니다. 오프라인/사용자 지정 경기에서 사용하세요.

확인한 원본 DLL SHA-256:
`3196ffcd56e58372b4f90c541d22572491da0ba0956d1b0b4b8b4d4dd303731d`

자동 검증: 전체 대체 유닛 등록·중복 제거, 서로 다른 버튼 46개 무손실 배치, 기본 0크기 버튼 템플릿 보존, 네이티브 그리드 유지, 작은 선택의 원래 HUD 크기 복구, 중첩 목록 제외, 실제 DLL 복사본의 세 파일 패치 및 IL 검사, 단축키 경계 수정, 중복 적용 차단, 복원 전 전체 무결성 검사, 세 DLL의 바이트 단위 원본 복원, 이전 패치 자동 전환. 게임 로그의 `[CFL All Units] Native command grid registered` 항목으로 새 HUD 후크를 확인할 수 있습니다.

v0.2.1 실제 화면 검증: Steam에서 새 사용자 지정 경기를 실행하고 일꾼 선택 상태의 아이콘·Q/W/E/R 단축키가 기존 우측 하단 HUD 안에 정상 정렬되는 것을 확인했습니다. 모든 진영·해상도 및 12개 초과 버튼의 실제 화면 검증은 아직 완료하지 않았습니다.

v0.2.2 실제 화면 검증: 일꾼 단일 선택 및 다중 선택에서 건설 아이콘과 C 표시가 11번째 칸에 나타나는 것을 확인했습니다. C 슬롯·복귀 Z 슬롯·추가 생산 버튼 충돌 방지·기본 빈칸 자리 유지 회귀 테스트를 추가했습니다. 사용자가 게임을 조작 중이어서 건설 메뉴 열기와 실제 건설 완료까지의 자동 조작 검증은 수행하지 않았습니다.

v0.2.3 위치 검증: 13/17/24/32/33/46/64개 버튼의 하단 HUD 겹침 방지, 1080/720 높이 Canvas의 화면 경계, 작은 선택으로 전환할 때 원래 위치 복구를 자동 테스트했습니다. 사용자의 요청에 따라 배포만 진행했으며 실행 중인 게임의 설치 파일 수정과 실제 화면 검증은 하지 않았습니다.

수정 파일은 `Carbon.Simulation.dll`, `Game.UI.dll`, `Carbon.UI.Unity.dll`이며 원본은 각각 `.cfl-original`로 백업합니다. 전체 상태/복구 기록은 Managed 폴더의 `CflMod.state.json`에 저장합니다. 적용 도중 문제가 생기면 복원하고, 변경된 게임 파일을 발견하면 덮어쓰지 않고 중단합니다. 원본 복원 시 자체 런타임도 제거합니다.

## 런처 업데이트

**런처 업데이트** 버튼은 이 저장소의 최신 정식 GitHub Release를 확인합니다. 새 버전의 `update.zip`과 `update.sha256`을 내려받고 SHA-256, ZIP 구성, 실행 파일 버전을 확인한 뒤 별도 버전 폴더에 설치합니다. 성공하면 `current.txt`를 교체하고 새 런처를 실행합니다. 이전 버전은 남아 있으며 `previous.txt`에 직전 버전이 기록됩니다. 업데이트 실패 시 기존 실행 파일은 유지됩니다. 이 기능은 런처/패처를 업데이트하며, 게임에 패치를 다시 적용해야 할 때는 원본 복원 후 재적용하세요.

## 개발 및 배포

```powershell
./scripts/build.ps1
# 출력: dist/Launcher.exe, build/*.zip

# 원본 게임 DLL을 대상으로 복사본 테스트 (게임을 종료한 상태)
./scripts/test-runtime.ps1 -Version 0.2.3 -GamePath 'C:\Program Files (x86)\Steam\steamapps\common\Crossfire Legion (Demo)'
# 결과: dist/versions/0.2.3/test-result.txt
```

코드 변경을 커밋한 뒤 다음 명령으로 새 버전을 배포합니다.

```powershell
./scripts/release.ps1 -Version 0.2.4
```

이 명령은 `version.txt`를 올리고 커밋·태그·푸시합니다. GitHub Actions가 Windows에서 빌드하고 Release에 런처 ZIP과 업데이트 파일을 게시합니다. 매 변경 배포 시 버전을 증가시켜야 하며, Actions 성공 이후 사용자의 업데이트 버튼에 반영됩니다. GitHub 인증/저장소 쓰기 권한과 Actions 사용 가능 상태가 필요합니다.

빌드 의존성: Mono.Cecil 0.11.6 (MIT). NuGet 패키지의 고정 SHA-256을 검증합니다. 런처 소스와 배포 설정만 Git에 포함하며 게임 DLL, 세이브 및 개인 설정은 포함하지 않습니다.
